# Updater test fixtures

`vrpc-test-key.private.pem` and `vrpc-test-key.public.spki.b64` are a **test-only**
ECDSA P-256 key pair. They exist so the C# trust layer and the Node signer can be
tested against the same bytes in both runtimes. They are committed on purpose and
**must never be added to `Modules/Deployment/Updates/TrustedUpdateKeys.cs`** — release builds
only trust production key IDs.

The production signing key never enters this repository. It lives outside every
repo (default: `%USERPROFILE%\.vrpc-release-keys\`) and is created with
`node packaging/update-keygen.mjs`; see `AUTO_UPDATER.md` §10.

Regenerating the vector (only if the payload schema or JCS rules change):

```powershell
cd vrpc-app\tests\VRPC.Tests\Fixtures\Updater
node ..\..\..\..\packaging\sign-manifest.mjs --payload-file vector.payload.json `
  --key vrpc-test-key.private.pem --key-id vrpc-test-key --out vector.manifest.json
$pub = (Get-Content vrpc-test-key.public.spki.b64 -Raw).Trim()
node ..\..\..\..\packaging\sign-manifest.mjs --verify vector.manifest.json --public-key $pub --canonical-out vector.canonical.txt
```

`jcs-vectors.json` is generated by the Node canonicalizer and checked against the
C# `Jcs` implementation in `TrustLayerTests`; keep both sides in sync if the
canonicalization profile ever changes.
